# Cockpit Playlist Editor

בייבוא Include Subfolders, קטגוריות משנה שומרות שדה אופציונלי `hierarchy_depth` ב־entry שלהן. שירים, קטגוריות ידניות וקטגוריות ראשיות אינם מקבלים שדה חדש; היעדר השדה משמעו עומק 0. פסי הקטגוריות מוצגים ברוחב 100%, 80%, 60% לעומקים 0, 1, 2 ומעלה, עם קצה התחלה קבוע לפי RTL/LTR. קטגוריות ללא עומק שומרות גם על יישור הטקסט הקיים; שמות קטגוריות משנה מיושרים לתחילת הפס.

התאימות נבדקה בקריאת קוד Cockpit המקומי (`../karaoke-app/app/ui/playlist_widget.py`, `_on_load_set`): טעינת קטגוריה קוראת את `is_category` ו־`title` ומתעלמת משדות נוספים. לכן השדה אינו משנה את טעינת ה־Playlist בקוד שנבדק. Cockpit אינו משמר אותו בשמירה חוזרת שלו, ולכן מידע העומק עלול להיעלם אם שומרים את הקובץ מתוך Cockpit. לא בוצעה בדיקת טעינה ידנית בתוכנת Cockpit, ואין כאן הבטחה לגרסאות אחרות שלה.

Prototype עצמאי לעריכת סדר ה־Playlist של Cockpit במפה צפופה ורב־עמודתית, עם שמירה ושליטה בגודל הפונט. אין תלות בפרויקט Cockpit.

## הפעלה ב־Windows

נדרש Python 3.10 ומעלה. מתוך תיקיית הפרויקט:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

לאחר ההתקנה אפשר ללחוץ פעמיים על `run.cmd`. בסביבת הפיתוח הנוכחית כבר הותקנו התלויות.

פתחו JSON באמצעות **Open Playlist** או **Ctrl+O**. אפשר גם להעביר נתיב בהפעלה:

תיקיית ה־Playlist האחרון שנפתח או נשמר נשמרת בהעדפות המקומיות, ומשמשת כתיקיית הפתיחה בהפעלה הבאה. בחירת קובץ שיר אינה משנה העדפה זו.

```powershell
.\run.cmd "c:\ישראלי 2\SETS2\להקות צבאיות, פסטיבלי זמר ועוד.json"
```

## Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py /path/to/playlist.json
```

## התנהגות והנחות

- הסדר הוא מלמעלה למטה בעמודה, ואז לעמודה שמימין; עברית מיושרת לימין בתוך הפריט.
- הפריסה מחושבת מגודל התצוגה וממדדי הגופן. רוחב העמודה המזערי שומר על קריאות; בחלון קטן או ברשימה ארוכה מופיעה גלילה אופקית. שמות ארוכים מקוצרים, ובמעבר עכבר מוצג השם המלא.
- קטגוריות נשארות באותו רצף, מודגשות בצבע ואינן ממוספרות.
- שם שיר נגזר מ־path ללא הסיומת, גם בנתיבי Windows וגם בנתיבי Linux. אם חסר שם קובץ, משתמשים ב־title; אם גם הוא חסר, מוצגת תווית חלופית.
- בהיעדר is_category הפריט נחשב לשיר. ערך קיים חייב להיות boolean.
- JSON נקרא כ־UTF-8, עם תמיכה ב־BOM. כל המבנה המקורי נשמר ב־`Playlist.data`, כולל שדות לא מוכרים; מודל התצוגה נפרד ממנו.
- שינויי סדר, הוספה והסרה נשארים בזיכרון עד Save או Save As. אין שמירה אוטומטית או Undo/Redo. פתיחה מחדש מחזירה את הנתונים האחרונים שנשמרו בקובץ.

## הוספה והסרה

לחצן ימני על שיר או קטגוריה פותח תפריט עם **Add Song** ו־**Add Category**. הפריט החדש נוסף מיד לפני הפריט שנלחץ. Add Song בוחר קובץ WRK/MIDI ושומר את נתיבו המלא; Add Category מבקש שם. קטגוריות ממורכזות ומודגשות ואינן ממוספרות.

**Remove Song** מסיר את השיר שנלחץ, או את כל השירים המסומנים כאשר הוא חלק מהבחירה. לחצן ימני על שיר שאינו מסומן בוחר אותו בלבד. **Remove Category** מבקש אישור ומסיר רק את הכותרת, בלי להסיר את השירים שאחריה. אין מחיקה של קובצי מוזיקה מהדיסק. לאחר פעולה הבחירה מתאפסת והמספור והפריסה מתעדכנים. ברשימה ריקה אפשר לפתוח את תפריט ההוספה בלחצן ימני על התצוגה.

פריטים חדשים משתמשים בשדות שבקובץ Cockpit לדוגמה: ערכי transpose/sync/delay/flags ו־tempo הם 0, תמונת רקע ריקה, dim הוא 45, יישור רקע center, 16 ערוצי mixer ברמה 127 ומצב chords אוטומטי. לא מועתקים פרטי שיר אחר ולא נשלפים נתוני MIDI/WRK בשלב זה. שדות הפריטים הקיימים נשמרים כמות שהם. התאימות נבדקה מול מבנה הקובץ שסופק; טעינה בתוכנת Cockpit עצמה לא נבדקה.

## שמירה

- **File > Save** / **Ctrl+S** שומר לקובץ הפעיל. לפני הדריסה הראשונה של כל קובץ קיים במהלך הפעלת האפליקציה, מופיע אישור מפורש עם הנתיב; ברירת המחדל היא No. אישור מוצלח נשאר בתוקף עד סגירת האפליקציה.
- **File > Save As…** / **Ctrl+Shift+S** בוחר קובץ חדש. הקובץ החדש הופך לקובץ הפעיל עבור Save בהמשך. בחירת קובץ קיים מחייבת אישור דריסה.
- נשמר כל מבנה ה־JSON, כולל שדות לא מוכרים, עברית ומספרים עשרוניים מדויקים. רק סדר entries משתנה בעקבות גרירה; העיצוב הטקסטואלי של ה־JSON נכתב מחדש בהזחה של שני רווחים וב־UTF-8.
- השמירה נכתבת תחילה לקובץ זמני באותה תיקייה, ורק לאחר כתיבה מוצלחת מחליפה את היעד. כשל כתיבה מוצג למשתמש.

## גודל פונט

בתפריט View יש גם **Increase Column Width**, **Decrease Column Width**, **Reset Column Width** עם **Ctrl+Right**, **Ctrl+Left**, **Ctrl+Down** בהתאמה. השינוי נעשה בצעדים של 24 פיקסלים, בטווח 120–1200, וכל העמודות אחידות. הרוחב שנבחר נשמר ב־`.user-settings.ini` ומשתלב עם גודל הפונט וכיוון העמודות. Reset מחזיר לרוחב האוטומטי המקורי לפי החלון והפונט. אין שינוי בנתוני ה־Playlist.

תפריט **Help** כולל מדריך בעברית, רשימת קיצורים מתוך הפעולות הממומשות וחלון About. החלונות פועלים ללא אינטרנט או דפדפן. תוכן העזרה נמצא ב־`help_ui.py`.

כפתור **→ LTR / ← RTL** ליד Open Playlist מחליף מיד את כיוון העמודות. בתוך כל עמודה ההתקדמות תמיד מלמעלה למטה. הכפתור משנה את התצוגה בלבד, ללא שינוי ב־entries, במספור או ב־JSON. גם הבחירה, הגרירה וסימון ההכנסה פועלים בשני הכיוונים. ההעדפה נשמרת בקובץ המקומי `.user-settings.ini` בתיקיית האפליקציה ונקראת בהפעלה הבאה.

**View > Font Size** מציע Increase, Decrease ו־Reset. הקיצורים הם **Ctrl++** (גם Ctrl+=), **Ctrl+-** ו־**Ctrl+0**. טווח הגדלים הוא 6–32 נקודות; Reset מחזיר ל־10.

גובה הפריטים ורוחב העמודות מחושבים מחדש לפי הגופן. בהגדלה מופיעות פחות עמודות בו־זמנית וייתכן צורך בגלילה אופקית. השינוי חל גם על שירים וגם על קטגוריות, בלי לשנות את סדר הנתונים או את הבחירה. הגודל אינו נשמר בקובץ ה־Playlist.

## בחירה וגרירה

- לחיצה בוחרת שיר אחד. Ctrl+Click מוסיף או מסיר שיר מהבחירה; Shift+Click בוחר טווח מהשיר שנלחץ לאחרונה, תוך דילוג על קטגוריות.
- גרירת שיר מסומן מעבירה את כל הבחירה לפי סדר השירים הנוכחי ברשימה. לחיצה ושחרור ללא גרירה על שיר מסומן משאירים רק אותו מסומן.
- אפשר לגרור ישירות בין עמודות. קו צהוב בין הפריטים מציין את מקום ההכנסה: החצי העליון של פריט מכניס לפניו, והחצי התחתון אחריו.
- קטגוריות אינן נבחרות או נגררות; אפשר להכניס שירים לפני או אחרי קטגוריה.
- לאחר השחרור הבחירה עוברת למיקום החדש והמספור מתעדכן. Escape מבטל גרירה.
- בחלון קטן, גרירה ליד הקצה הימני או השמאלי של התצוגה מפעילה גלילה אופקית אוטומטית.

לבדיקה ידנית: סמנו את שיר 12 ועוד שני שירים עם Ctrl, גררו אחד מהם אל מתחת לשיר 140 ושחררו כשהקו הצהוב מופיע. שמרו עם Save As לקובץ חדש ופתחו אותו מחדש כדי לבדוק שהסדר נשמר. נסו שינוי פונט ו־Reset.

## מבנה ובדיקות

`app.py`: חלון, פתיחה, שמירה, תפריטים וחיבור שינוי הסדר; `playlist.py`: מסמך, העברת שירים, סריאליזציה ותצוגת נתונים; `layout.py`: חישוב פריסה; `view.py`: ציור, בחירה, גרירה, גופן וגלילה. קובצי הבדיקות: `tests/test_prototype.py`, `tests/test_editing.py`, `tests/test_save_font.py`.

```powershell
$env:COCKPIT_TEST_PLAYLIST = 'c:\ישראלי 2\SETS2\להקות צבאיות, פסטיבלי זמר ועוד.json'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

בדיקת הקובץ האמיתי בודקת גם SHA-256 לפני ואחרי ומפיקה צילומי חלון ב־`test-output`, כולל סימון הכנסה והקבוצה לאחר העברה. בדיקות הבחירה משתמשות ב־QTest; בדיקות הגרירה שולחות אירועי Qt לחלון בפועל ומדמות את לולאת הגרירה של מערכת ההפעלה. גרירה בעכבר פיזי ו־Linux לא נבדקו בסביבה זו.

בדיקות Save ו־Save As כותבות בפועל לעותקים זמניים של הקובץ האמיתי ופותחות אותם מחדש; תיבות בחירת הנתיב ואישור הדריסה מדומות בבדיקות. נבדקים גם ביטול, כשל כתיבה, שימור שדות ודיוק מספרי. בדיקות הפונט מציגות את החלון בגדלים 6, 10, 16, 24 ו־32 ובודקות את הקיצורים ואת Reset.
